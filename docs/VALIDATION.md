## Migrations, startup, and infrastructure

Before the workspace migration, SQLite's backup API created consistent copies of all three normal databases under `.data/backups/20261114-192321/`. Migration `0002` is additive. Ordinary startup seeds missing synthetic fixtures without resetting the user's existing chart or decisions.

SQLAlchemy compiled PostgreSQL DDL for all 28 shared/local tables and their indexes. Compose YAML parsed with five services and three independent database volumes. The PowerShell launcher parsed without errors. Its dotenv reader was exercised on Windows with spaces, literal comment characters, UTF-8 BOM input, and quoted hospital-configuration JSON.

The launcher checks ports 3000/8000 before migrations, captures backend stdout/stderr in `.data/logs/`, waits for a positive health response, and invokes Next.js through Node to avoid the batch termination prompt. Frontend proxy/network failures are covered by the browser tests above. The original reported `ECONNRESET` cannot be retrospectively attributed to a particular backend exception because the older launcher did not retain its process logs.

Its occupied-port rejection and actual startup against the normal saved databases were exercised. The frontend root, same-origin API health, and FastAPI `/docs` returned 200. The network clinician authenticated, switched between both authorized hospitals, opened every permitted local chart/timeline, and successfully requested `/api/sync` in each workspace. No normal database reset was performed. All 41 pre-launch account, immutable source-version, canonical-version, and clinical-event rows retained identical SHA-256 row hashes after startup and these checks. The running default configuration reports manual transcription and the local organizer.

**Docker/PostgreSQL container execution was not performed:** Docker is unavailable on this machine. DDL compilation and YAML parsing do not replace a PostgreSQL/Compose integration run. The Linux launcher and Docker images were not executed here.

## External integration limits

OpenAI provider request construction and response validation were exercised with `httpx.MockTransport`. **Live transcription and model calls were not executed because external credentials were unavailable.** The default manual transcript and local organizer workflow was verified end to end. See [PROVIDERS.md](PROVIDERS.md) for configuration and privacy/retention boundaries.

Hospital adapters use explicitly synthetic local formats. No live Epic, Oracle Health, external EHR write-back, production signature, distributed transaction, full FHIR conformance, clinical validation, security certification, WCAG certification, or HIPAA compliance is claimed. Linking independently published global identities remains an explicit reconciliation limitation; the API refuses to silently move their history.
